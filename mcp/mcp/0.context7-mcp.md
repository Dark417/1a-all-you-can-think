## 1. What it is

Context7 is an MCP server that gives an LLM coding agent **up-to-date library documentation** on demand. Instead of relying on stale training data, the agent calls two tools:

1. `resolve-library-id` — "which library does the user mean?" → returns Context7 IDs like `/vercel/next.js`
2. `query-docs` — "give me the docs for this concept in that library" → returns a text blob of reranked doc snippets

The server itself does no indexing or retrieval. It is a **thin, stateless proxy** to `https://context7.com/api`, whose value is (a) speaking the MCP protocol correctly to many clients (Cursor, Claude Code, Codex, Gemini CLI, Windsurf…) and (b) writing tool descriptions that steer the model well.

## 2. Why this project

- Installed by default in many editor MCP configs; one of the most-used community MCP servers.
- Small: one entry file + a `lib/` folder. You can read the whole thing in 20 minutes.
- Yet it touches every real-world MCP concern: two transports, OAuth discovery, JWT validation, elicitation, Zod input schemas, tool annotations, CORS, proxies/custom CA, error mapping, port fallback.

## 3. Architecture at a glance

```
 MCP client (Cursor / Claude Code / ...)
        │  JSON-RPC over stdio  ──or──  Streamable HTTP (POST /mcp)
        ▼
 ┌──────────────────────── packages/mcp/src/index.ts ────────────────────────┐
 │  commander CLI → pick transport                                            │
 │  createMcpServer(): McpServer + 2 registerTool()                            │
 │  stdio: serveStdio(factory)      http: express + createMcpHandler(factory)  │
 │  ClientContext (apiKey, ip, ide, transport) via AsyncLocalStorage / globals │
 └──────────────┬──────────────────────────────────────────────┬─────────────┘
                │ searchLibraries()                             │ fetchLibraryContext()
                ▼                                               ▼
        GET /api/v2/libs/search                         GET /api/v2/context
        ?query&libraryName                              ?query&libraryId
                         (headers from lib/encryption.ts: bearer key,
                          encrypted client IP, IDE name/version, transport)
                                   ▼
                        https://context7.com backend
```

Key property: **no state between requests**. HTTP mode builds a fresh `McpServer` per request; stdio mode has one process per client with three module-level globals.

## 5. The two tools

Both are registered in `createMcpServer()` with `server.registerTool(name, {title, description, inputSchema, annotations}, handler)`.

### `resolve-library-id`

- Input: `{ query, libraryName }` — `libraryName` is what's searched; `query` is the user's task, used server-side to rank candidates.
- Output: plain text list, one block per library:
  ```
  - Title: Next.js
  - Context7-compatible library ID: /vercel/next.js
  - Description: ...
  - Code Snippets: 4127
  - Source Reputation: High        ← trustScore ≥7 High, ≥4 Medium, else Low
  - Benchmark Score: 92
  - Versions: v15.0.0, v14.3.0
  ----------
  ```
- The description is long and prescriptive: "MUST call before query-docs unless the user gave `/org/project`", a 5-step selection rubric, "do not call more than 3 times". This is **prompt engineering living in the tool schema** — the main lever the server has over model behavior.

### `query-docs`

- Input: `{ libraryId, query }`. The `query` description coaches the model to be specific and one-concept-per-call ("Good: 'React useEffect cleanup function examples'; Bad: 'hooks'").
- Output: whatever text the `/v2/context` endpoint returns; empty body → a canned "invalid library ID, call resolve-library-id" message.

### Annotations

Both tools declare `readOnlyHint: true, destructiveHint: false, idempotentHint: true, openWorldHint: true`. Clients use these to skip confirmation prompts and to understand the tool reaches an external system.

## 6. Request lifecycle

1. Client sends `tools/call`.
2. SDK validates params against the Zod schema. Before validation, `z.preprocess(aliasArgs(...))` rewrites hallucinated key names (`userQuery`→`query`, `context7CompatibleLibraryID`→`libraryId`). Models often echo phrasing from the description instead of the literal key; this avoids a validation failure and a wasted round-trip.
3. Handler calls `getClientContext(toolCtx)`:
   - HTTP: reads the per-request `ClientContext` stored in `AsyncLocalStorage` by the express layer.
   - stdio: uses globals set at startup (`stdioApiKey`, `stdioSessionId`) and at `oninitialized` (`stdioClientInfo`).
   - Either way, prefer client name/version from the request `_meta` envelope (2026 protocol) over the handshake/User-Agent fallback.
4. `api.ts` builds the upstream URL, `generateHeaders(ctx)` adds telemetry + auth headers, `fetch` with `AbortSignal.timeout(60_000)`.
5. Non-2xx → `parseErrorResponse` prefers the backend's `message`; otherwise maps 429/404/401 to actionable text (e.g. "create a free API key at …"). Errors are **returned as tool text**, not thrown — the model sees them and can react.
6. If the backend set `X-Context7-Auth-Prompt: 1`, `ctx.shouldPrompt = true`; the handler then calls `maybeElicitAuthSignIn()` (see §8).
7. Return `{ content: [{ type: "text", text }] }`.

## 7. Transports: stdio vs HTTP

Selected by `--transport stdio|http` (default stdio). Incompatible flags are rejected: `--api-key` only for stdio, `--port` only for http.

### stdio (local, one process per editor session)

```ts
serveStdio(() => {
  const server = createMcpServer();
  server.server.oninitialized = () => { /* capture client name/version */ };
  return server;
}, { onerror });
```
- API key from `--api-key` or `CONTEXT7_API_KEY`.
- A `randomUUID()` session ID per process, sent upstream for rate-limit bucketing.
- Exits on stdin `end`/`close` and `SIGHUP` so it never outlives the editor.
- All logging goes to `console.error` — **stdout is the protocol channel**, so nothing else may write to it.

### HTTP (hosted at `mcp.context7.com`)

```ts
const mcpHandler = createMcpHandler(() => createMcpServer(), { keepAliveMs: 0, onerror });
const nodeHandler = toNodeHandler(mcpHandler, { onerror });
app.all("/mcp",       (req, res) => handleMcpRequest(req, res, false)); // anonymous
app.all("/mcp/oauth", (req, res) => handleMcpRequest(req, res, true));  // auth required
```
- **Stateless**: fresh `McpServer` per request, no `Mcp-Session-Id`, no session store → trivially horizontally scalable. Legacy-protocol GET/DELETE session ops get 405.
- `keepAliveMs: 0` disables SSE heartbeats. The comment explains a real outage: a cancelled request produces no response, the stream never closes, heartbeats kept it "alive" until a 1200s gateway cap. With no heartbeats the idle stream is reaped at 300s instead.
- CORS middleware allows the MCP headers (`Mcp-Session-Id`, `Mcp-Protocol-Version`, `Mcp-Method`, `Mcp-Name`, the API-key headers) so browser-based clients pass preflight.
- Port fallback: on `EADDRINUSE` retry `port+1` up to 10 times.
- Extra routes: `/ping`, `/.well-known/oauth-protected-resource` (RFC 9728), `/.well-known/oauth-authorization-server` (proxied from Clerk), `/.well-known/openai-apps-challenge`, JSON 404 catch-all.

## 8. Auth and client context

Three tiers of caller:

| Tier | How the key arrives | Effect |
| --- | --- | --- |
| Anonymous | none | low rate limit; backend may ask the server to nudge sign-in |
| API key (`ctx7sk…`) | stdio: flag/env · http: `Authorization: Bearer`, `Context7-API-Key`, `X-API-Key` (+ underscore variants) | forwarded upstream as `Authorization: Bearer` |
| OAuth JWT | `Authorization: Bearer <jwt>` on `/mcp/oauth` | `validateJWT` checks signature/issuer via JWKS (Clerk for users, Context7 EMA issuer for enterprise id-jag), 401 with JSON-RPC error `-32001` on failure |

`WWW-Authenticate: Bearer resource_metadata="…/.well-known/oauth-protected-resource"` is set on every MCP response so clients can discover the authorization server per the MCP auth spec.

**Elicitation nudge** (`auth-prompt.ts`): when anonymous and `shouldPrompt`, and the client advertised the `elicitation` capability, the server fires `server.server.elicitInput({ message, requestedSchema: { choice: enum[...] } })` fire-and-forget. The message contains a copy-paste `npx ctx7 setup --claude --mcp --stdio -y` command tailored to the detected IDE. It is delivered **to the human via the client UI, not into the tool result**, so it can't be mistaken for prompt injection. Only works on 2025-era stdio sessions — HTTP is stateless (no initialize → no capabilities) and the 2026 protocol removed push-style server→client requests.

**Client IP**: on HTTP, `getClientIp` walks `X-Forwarded-For` respecting trusted proxies, then `encryption.ts` AES-256-CBC-encrypts it (`iv:ciphertext` hex, key from `CLIENT_IP_ENCRYPTION_KEY`) before forwarding as `mcp-client-ip`. The backend uses it for anonymous rate limiting without the proxy leaking raw IPs in logs.

## 9. Notable engineering details

- **Alias preprocessing in the schema** (`aliasArgs`) — transport-agnostic tolerance for LLM key hallucinations; returns a remapped copy so the raw wire params stay untouched.
- **Capabilities `{ prompts: {}, resources: {} }` declared despite having none** — makes the SDK answer `prompts/list` / `resources/list` with empty arrays for clients that call them unconditionally, instead of "method not found".
- **`instructions` field on the server** — a server-level system-prompt hint telling the model when to use (and not use) Context7: "even for well-known libraries… prefer over web search".
- **Corporate network support**: `HTTPS_PROXY`/`HTTP_PROXY` → undici `ProxyAgent`; `NODE_EXTRA_CA_CERTS` appended to the default CA bundle. Set once at module load via `setGlobalDispatcher`.
- **Timeouts with numbers**: 60s per upstream call, justified in a comment by observed p99.9 ≈ 3.2s and max < 30s.
- **Every failure becomes model-readable text** — never a thrown error, never an empty result.
- **Version from `package.json`** at runtime (`SERVER_VERSION`), sent upstream as `X-Context7-Server-Version` for telemetry.
- **Testing**: `integration.test.ts` wires an in-memory MCP client to the server, so tool descriptions/schemas are asserted without a network.

## 10. Running it locally

Requires Node ≥ 20.18.1 and pnpm.

```bash
cd mcp/context7
pnpm install
pnpm build:mcp
node packages/mcp/dist/index.js                     # stdio
node packages/mcp/dist/index.js --transport http --port 3000
curl localhost:3000/ping
```

Or without cloning, in a Claude Code / Cursor MCP config:

```json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp", "--api-key", "ctx7sk-..."]
    }
  }
}
```

Remote: `https://mcp.context7.com/mcp` with header `CONTEXT7_API_KEY: ctx7sk-...` (or `/mcp/oauth` for OAuth).

Debug with MCP Inspector: `npx -y @modelcontextprotocol/inspector npx @upstash/context7-mcp` (the server has `allowUnknownOption()` precisely so wrappers like this can pass extra flags).

## 11. MCP concepts you learn from this codebase

| Concept | Where |
| --- | --- |
| `McpServer` + `registerTool` with Zod input schema | `createMcpServer()` |
| Tool annotations (`readOnlyHint` etc.) | tool definitions |
| Server `instructions` and declared `capabilities` | `new McpServer(info, options)` |
| stdio transport, stdout hygiene, lifecycle signals | `main()` else-branch |
| Streamable HTTP, stateless per-request server, CORS | `main()` http-branch |
| OAuth protected-resource metadata, `WWW-Authenticate`, JWT/JWKS | routes + `jwt.ts` |
| Elicitation (server asks the user a question) | `auth-prompt.ts` |
| Client identification via `_meta` envelope vs `initialize` | `utils.ts` `envelopeClientInfo` |
| Per-request context without threading params | `AsyncLocalStorage` |
| Tool result = `content: [{type:"text"}]`, errors as text | handlers + `api.ts` |

## 12. Interview-style questions

1. Why is the HTTP mode stateless (new server per request)? What do you lose (elicitation, sampling, session-scoped state) and gain (scale-out, no sticky sessions)?
2. Why does the stdio server log to stderr only? What happens if a dependency prints to stdout?
3. Where should input-name aliasing live — in the schema, in the handler, or at the transport? Why did they choose the schema?
4. Why return upstream errors as tool text instead of JSON-RPC errors? How does the model's behavior differ in each case?
5. The `keepAliveMs: 0` decision traded away heartbeats to make hung streams reapable. Under what workload would that be the wrong trade?
6. How does `WWW-Authenticate: Bearer resource_metadata=...` enable an MCP client to bootstrap OAuth with zero configuration?
7. Why encrypt the client IP before forwarding instead of just trusting the internal network?
8. Two tools vs one tool that does search+fetch: what does the two-step design buy in terms of model control and token cost?
9. How would you add caching to `query-docs`? What is the cache key, and how does the per-request server model complicate it?
10. `resolve-library-id` says "do not call more than 3 times". Why is that in the tool description rather than enforced server-side?
